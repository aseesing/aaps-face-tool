Making a watch face design with facetool

How to make or change a design of the AAPS Custom watch face with the editor facetool, step by step, for people and for AI agents. A design is a zip with one JSON file, pictures and fonts. The editor shows it as the AAPS watch engine draws it (AAPS CWF) and as a Watch Face Format face (WFF 4 and WFF 2).

Three places to read. This page: the way of working. The manual of the design format (docs/watchface-animation.html in the AAPS checkout that aapsDir names): every key, formula and template, and what WFF can do. docs/face-editor.md in this repository: every command with all its arguments. You never need a browser for the manual: facetool manual --list shows its chapters and facetool manual <id> prints one as plain text. In the browser page of the editor, both pages are in the Help menu.

1. Who this is for, and two ways to work

2. Set-up, once

  1. local.properties in this repository (not checked in): 
    sdk.dir=<your Android SDK>
aapsDir=<an AAPS checkout with the layer engine and the WFF planner>
designsDir=<the designs repository aaps-watchfaces>
    aaps-commit.txt names the AAPS commit the editor was tested with. An answer warns when aapsDir is on another commit.
  2. Build the command line and the class path of the render server, in this repository: 
    ./gradlew :editor-cli:installDist :editor-server:editorClasspath
    The program is then tools/facetool. Build again after the code of the editor changed or the AAPS checkout moved. If tools/facetool says "facetool is not built", this step is missing. When a server still runs from before the build, answers say "restart needed": run facetool stop.
    On a computer that has a lock script for Gradle (~/.claude/bin/gradle-locked.sh), run the build through it, as every Gradle build there.
  3. Pack, only for WFF face APKs and the face zip (facetool wff apk): sh tools/build-pack.sh, see docs/wff-apk.md. The previews, wff plan and wff compare do not need Pack.
  4. Start the page: tools/facetool gui opens it in the browser. tools/facetool gui --project <folder> opens it on one project. The first command that draws starts the render server (about 5 seconds). It listens only on this computer and stops by itself after 2 hours without a request.

Below, facetool stands for tools/facetool of this repository. You work in a project folder, not in this repository, so call it by its full path (<aaps-face-tool>/tools/facetool) or put tools on your PATH.

3. The loop, step by step

A design is edited as a project folder: the files of the zip, unpacked, and a hidden folder .facetool with the history, the scene and the pictures. Inside the folder every command finds the project by itself. Elsewhere give --project <folder>.

Every file in the project folder goes into the zip. Keep your patch files, scene files, notes and source pictures outside the project folder, for example in a folder next to it. facetool info lists the files that will be packed.

Step 1: new or open

facetool new "First Light" --dir <folder>        # an empty design: metadata, a background colour, no layers
facetool open <design.zip> --dir <folder>        # an existing design

Without --dir the folder is ~/Projects/aaps-face-editing/<name>. open never unpacks over a folder with other content. The name you give is the title of the design (metadata.name); its file name (metadata.filename) is the same with _ for the spaces. A new design has a wake of 6000 ms and no layers.

The one thing to know before the first layer: a layer shows only while the wake animation plays, unless it has "rest": 0. rest is a moment of the wake in seconds, not a switch: with "rest": 0 the layer also stays on the face after the wake, drawn as it is at second 0. Give it to everything that must always show: the background art, the clock, the glucose.

Step 2: read

facetool info                          # name, sizes, counts, the wake length, the share of the zip limit
facetool list layers                   # L0, L1, ... with what each draws; also: list views, list resources
facetool show 'animation.layers[2]'    # one part as JSON; without a path: the whole design
facetool expand                        # the plain layers the engine reads after the templates
facetool keys layer                    # the keys the engine knows; also: keys values, keys functions
facetool manual --list                 # the chapters and sections of the manual
facetool manual source-text            # one of them as plain text

Quote a path with brackets. A path counts the entries of animation.layers in the JSON. The engine and the WFF lint count the plain layers after the templates are filled in (L24); expand shows both.

Step 3: change

facetool set animation.durationMs 4000                       # the value is JSON
facetool set background.color --text "#0B1530"               # --text: the value is a plain text
facetool layer add '{"shape": "circle", "x": 200, "y": 200, "radius": 20, "color": "#FFFFFF"}'
facetool apply patch.json                                    # many edits in one step, all or none
facetool res add Star.png                                    # a picture or a font; the key is the file name without extension
facetool undo                                                # takes the last change back

A patch file is a JSON list of edits: {"op": "set", "path": ..., "value": ...}, {"op": "unset", "path": ...}, {"op": "insert", "path": ..., "value": ...} and {"op": "move", "from": ..., "to": ...}. You may also edit CustomWatchface.json with any tool: the editor reads the folder new at each command, and undo also takes back a change from outside. When a command finds such a change (also a file you put into the folder), it says "The folder was changed outside the editor: history entry N". That is a note, not an error: the change got its own entry in the history. The history numbers count the changes of the project; facetool history lists them, and save keeps the zip it replaces as .facetool/history/<N>.zip.

A text layer is placed by a point: x is its left end, its middle or its right end (align), and y is the line the letters stand on (valign can change that). A picture has a rect; a shape has x, y and its own size keys. See facetool manual source-text and facetool manual key-place.

Step 4: look

facetool render                        # the face at rest: .facetool/out/render/render.png
facetool render --annotate --grid      # with a box and a number on each layer, and the grid of 400 units
facetool render --wake 2               # one moment of the wake
facetool render --batch scenes.json --out pictures     # many scenes in one call
facetool wake --sheet                  # the whole wake as one picture, the time under each frame
facetool options                       # one picture per choice of each option, as one sheet
facetool looks                         # which looks are on, and a sheet of them
facetool pick 108 160                  # which layers and views draw this point (design units)

A scene is everything outside the design that changes the picture: the time, the glucose, the weather, the choices of the options, always-on. --set key=value changes one key for one command, for example --set sgv=250, --set options.stars=2, --set ambient=true or --set time=2026-12-25T18:30:00. facetool scene shows the scene of the project, facetool scene --presets the ready scenes (high, low, no-data, old-reading, night, christmas, low-battery). The glucose of a scene is in mg/dl; the default scene shows it in mmol/l (--set units=mgdl changes that).

Every picture command answers with the path of its PNG. Open that file and look at it. A picture is drawn by the real engine of the AAPS commit in aapsDir.

Step 5: check

facetool lint                          # errors and warnings of the engine and the editor, and the WFF lint of 4 and 2
facetool wff plan                      # where each view and layer goes on a WFF face
facetool wff compare                   # the engine next to WFF 4 and WFF 2, the differing pixels in red
facetool wff wake --sheet              # the WFF face in the seconds after the screen comes on
facetool wff render --set ambient=true # the always-on face of the WFF face

An answer "No findings." from lint is the good case. Fix every error. Read every warning: a WFF line with ! means something looks or behaves in another way on a WFF watch. What each line of the plan means is in the manual, facetool manual wff-parts; what WFF cannot do is in facetool manual wff-limits. The first WFF command of a design builds the face; that takes from some seconds to about a minute.

Step 6: save

facetool save --out First_Light.zip    # a new project has no zip yet: name it
facetool save                          # later: the zip the project came from
facetool save --as Other_Name.zip      # this zip becomes the zip of the project

save checks first: the JSON reads in the engine, every picture and font the JSON names is in the folder, and the zip is under the size limit of the watch. An error stops the save with exit code 1. It also draws the preview picture new (CustomWatchface.png or .jpg, 400 x 400), the picture the phone shows in its list of designs: the face at rest in the default scene. --keep-preview keeps a picture you made yourself.

4. How to keep the turns few

  • Read the answers, not the screen. Add --json to get one JSON object: file (the PNG), files (a batch), warnings, findings (the lint). The exit code says how it went: 0 done; 1 done, but a check has errors; 2 wrong use; 3 the design does not read; 4 the server failed.
  • One patch, not ten sets. Write all edits of one idea into a patch file and run apply. It is all or none, and one undo takes it back.
  • One batch, not ten renders. render --batch draws a list of scenes in one call, in well under a second for a small design. Each call of the command line costs about half a second to start.
  • Sheets. wake --sheet, options, looks and wff compare each give one picture that shows many. Look at one sheet, not at many frames.
  • render --annotate --grid before you move things. It shows where each layer draws, in design units, so you get a place right the first time.
  • Check once at the end of a change, with lint. It includes the WFF lint; --no-wff leaves that out when you only want the engine's errors fast.
  • Read one section of the manual, not the whole: facetool manual source-text, facetool manual templates, facetool manual options.

5. A worked example: First Light

A small new design from nothing: a dark blue background, stars, a clock text, a glucose text coloured by its level, a star that turns and fades during the wake (from a template), and one option for the number of stars. Every command and every JSON on this page was run, and the answers are the real ones (the paths are made short). The three files of the example are in this repository, in docs/making-a-design-example/: Star.png, patch.json and scenes.json. Below, $EX stands for the full path of that folder.

1. A new project

$ facetool new "First Light" --dir First_Light
Made the new design First Light in First_Light
$ cd First_Light
$ facetool set background.color --text "#0B1530"
Done: history entry 1.
$ facetool set metadata.author --text "Example"
Done: history entry 2.

2. A picture

The wake needs one picture, Star.png: a yellow star on a clear background, 96 x 96 pixels, 642 bytes. For your own design, draw a picture with any tool. Keep pictures small: a layer scales a picture to its rect anyway. res add copies the file into the project folder.

$ facetool res add $EX/Star.png
Done: history entry 3.

3. The design, as one patch

patch.json sets the option, the wake length, one template and four layers:

$ facetool apply $EX/patch.json
Done: history entry 4.
$ facetool list layers
L0    shape circle x60
L1    text clock()
L2    text glucose(v_sgv)
L3    use twinkle
$ facetool info
First Light by Example (First_Light)
Sizes: zip 1871 bytes (0 % of the limit of the watch), JSON 3015 bytes, 2 resources 837 bytes
Counts: 4 layers, 1 views, 1 templates, 1 options, 0 looks
Wake: 4000 ms

4. Look

$ facetool render --annotate --grid
Wrote First_Light/.facetool/out/render/render.png (450 x 450, at rest)

The picture has a box with L1 round the clock and L2 round the glucose, and the grid shows that both are centred on x = 200. Then seven scenes in one call. scenes.json:

[
  {"out": "rest.png"},
  {"sgv": 250, "direction": "↑", "out": "high.png"},
  {"sgv": 58, "direction": "↓", "out": "low.png"},
  {"wake": 2, "out": "wake.png"},
  {"options.stars": 2, "out": "many-stars.png"},
  {"time": "2026-11-17T23:30:00", "units": "mgdl", "out": "night-mgdl.png"},
  {"ambient": true, "out": "always-on.png"}
]
$ facetool render --batch $EX/scenes.json --out ../pictures
Wrote pictures/rest.png (450 x 450, at rest)
Wrote pictures/high.png (450 x 450, at rest)
Wrote pictures/low.png (450 x 450, at rest)
Wrote pictures/wake.png (450 x 450, 2.0 s into the wake)
Wrote pictures/many-stars.png (450 x 450, at rest)
Wrote pictures/night-mgdl.png (450 x 450, at rest)
Wrote pictures/always-on.png (450 x 450, always-on)
7 pictures in 0.49 s.
$ facetool wake --sheet --fps 2
Wrote the contact sheet First_Light/.facetool/out/wake/wake.png: 9 frames from 0.0 s to 4.0 s at 2 a second.
$ facetool options
Wrote the sheet First_Light/.facetool/out/options/options.png: 3 pictures (stars 0: None; stars 1: Few; stars 2: Many)

What the pictures showed: 13.9 in yellow for 250 mg/dl, 3.2 in red for 58, the star on top only in the frames from 0.5 s to 3.5 s of the wake, and an empty always-on picture. That last one is a real finding: the engine does not draw rest layers of texts, pictures and shapes in always-on. A design that must show the time and the glucose in always-on on the AAPS Custom watch face needs the classic views time and sgv for them (facetool manual views). The WFF face does show both in always-on: there they are live parts.

5. Check

$ facetool lint
info [wff4] -: the layers [3] fade in and out with the wake: 9 frames each
info [wff2] -: the layers [3] fade in and out with the wake: 9 frames each
$ facetool wff plan
First Light -> WFF 4
   background             bake         picture 0     static picture
   L0 circle              complication data          reads option (60 copies): in the data picture
   L1 text clock()        live                       clock text: DigitalClock with the zip font
   L2 text glucose(v_sgv) complication glucose       glucose text: live in the glucose slot
   L3 Star                bake         loop          moves in the wake: frames when it only shows in the wake, else its rest pose
Slots 2 / 8   static pictures 1
   slot 10 glucose (RANGED_VALUE)
   slot 20 data (SMALL_IMAGE)
Errors 0   Warnings 0

Pictures: 1 static, 3 loops with 39 frames of 200
$ facetool wff compare
Wrote First_Light/.facetool/out/wff-compare/compare.png: the engine, WFF 4 and WFF 2 (player), and under them the pixels that differ from the engine in red.
WFF 4: 1.17 % of the pixels differ from the engine
WFF 2: 1.17 % of the pixels differ from the engine

No errors and no warnings. The plan says: the clock and the glucose are live on WFF, the star plays as frames, and the stars go to the data picture because they read an option. The compare picture shows red only round the two live texts: their edges lie a little differently, and the WFF glucose is written "6,7" where the engine writes "6.7" (the glucose slot shows the text of the phone, with the decimal sign of the phone; the scene key decimalSign sets it).

6. Save

$ facetool save --out ../First_Light.zip
Saved First_Light.zip (1871 bytes, 0 % of the limit of the watch)

6. Rules a design must keep

The zip stays under about 320 KB. A larger design never reaches the watch, and there is no error. save checks it and stops; info shows the share used. Use jpg for photos, small pictures, and fonts with only the signs you use.
  • Every picture and font is in the zip. A layer names a picture by its file name without the extension. Add files with res add, one file at a time. The fonts of the app (default_bold, sans_serif, ...) need no file.
  • Designs live in the designs repository aaps-watchfaces (cwf-designs). The zips there are made by generators (its src/test/kotlin): a change in such a zip is lost at the next build of the designs. open, info and save say so. To keep a change of a generated design, change its generator.
  • Never merge two design zips. There is no command for it; do not do it by hand.
  • Face APKs are only for emulator checks. Never install one on a real watch or phone from here. wff emulator refuses a real watch.
  • Do not share faces made from other people's designs. They are only for checking the converter.
  • Pictures are not proof. Do not call a design "working" from the previews alone. The owner tries it on a watch.

7. Where a finished design goes

A new design is a project folder under ~/Projects/aaps-face-editing/<name> (the default of new and open), with its zip next to it or where save --out puts it. The owner of the designs decides whether the zip is copied into aaps-watchfaces/cwf-designs. An agent asks before it writes anything into that repository, and never changes another project folder than the one it was given.
